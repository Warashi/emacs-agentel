#+title: agentel

An Agent Client Protocol (ACP) client for Emacs, built on acp.el.

It is written for [[https://github.com/agentclientprotocol/claude-agent-acp][claude-agent-acp]] and aims at the experience of the
GUI agent apps:

- each subagent gets a buffer of its own, and the parent shows one item
  per subagent with its state and latest tool call
- each tool call takes one line, led by why the agent calls it
- running subagents and background tasks stay pinned above the prompt
- slash commands complete at the start of the prompt
- the header line shows the state, project and title of the session,
  then model, effort, mode, context usage and cost
- model, effort and mode are start options of a Lisp function
- a session list shows every running session, its subagents and
  whether it waits for an answer
- permission requests and AskUserQuestion forms are answered in the
  transcript or from the minibuffer

agentel does not offer file system or terminal capabilities; the agent
uses its own tools.

For Claude subagent sessions, agentel advertises both the draft ACP
=subagents= capability and the =nativeSubagentSessions= capability of
the JetBrains AIR extension.  The latter is needed when the ACP SDK
does not preserve the draft field; without negotiation the adapter
puts child output in the parent's session instead.

[[https://docs.github.com/copilot/how-tos/copilot-cli][Copilot CLI]] (=copilot --acp=) runs too, with the same model, effort
and mode options.  A subagent of Copilot CLI shows in the transcript of
the parent as one tool call, whose content is the reply of the
subagent; what the subagent does meanwhile is left out.  Copilot CLI
does not mark the replies and thoughts of a subagent started in the
background, so those still mix with the parent's, as do the replies of
all subagents in a conversation loaded again with =/resume=.

* Usage

=claude-agent-acp= must be on =PATH= and logged in (=claude auth login=).
For Copilot CLI, =copilot= must be on =PATH= and logged in (=copilot
login=).

- =M-x agentel= starts a session in the current project; with a prefix
  argument it asks for the directory.
- From Lisp, pass the settings to start with:

  #+begin_src emacs-lisp
  (agentel-start :cwd "~/src/project/" :model "opus" :effort "high" :mode "plan")
  #+end_src

  =:session-id= loads an earlier session instead of creating one.

** Choosing the agent

=agentel-agents= names the agents and their command lines, and
=agentel-default-agent= is the one =M-x agentel= starts.  =:agent=
starts another one; =/clear= and =/resume= keep the agent of the
session:

#+begin_src emacs-lisp
(agentel-start :cwd "~/src/project/" :agent 'copilot :model "gpt-5.5" :mode "plan")
#+end_src

=:model=, =:effort= and =:mode= take the values the agent lists, or
their names as =C-c C-o= shows them: Copilot CLI takes =plan= for its
Plan mode, whose value is a URL.

** Running the agent through a wrapper

=agentel-command-prefix= is put in front of the agent command, so the
agent can run in a container or a sandbox while =agentel-agents=
keeps the plain command.  It is a list of strings, or a function that
receives the session directory and returns one.  For Docker, mount the
directory and keep stdin open; do not allocate a TTY (=-t=), since ACP
speaks JSON over stdio:

#+begin_src emacs-lisp
(setq agentel-command-prefix
      (lambda (cwd)
        (list "docker" "run" "--rm" "-i"
              "-v" (format "%s:%s" cwd cwd) "-w" cwd
              "my-agent-image")))
#+end_src

The prefix is the same for every agent, so the image needs the
commands of all agents in =agentel-agents= that you start.

=agentel-environment= goes to the first program of the prefix; pass
the variables on yourself if the wrapper does not (=docker run -e=).

** Session buffer

The buffer is named after the project of the session directory
(=project-name=), or after the directory outside a project.  The
transcript is read-only; the prompt is edited below it like any other
text.

| Key           | Command                                              |
|---------------+------------------------------------------------------|
| =C-c C-c=     | send the prompt                                      |
| =C-c C-k=     | cancel the current turn                              |
| =C-c C-a=     | answer the oldest question                           |
| =C-c C-o=     | change a session option                              |
| =C-c C-m=     | change the mode                                      |
| =C-c C-l=     | list the sessions                                    |
| =C-c C-f=     | toggle =agentel-focus-mode=                          |
| =C-c C-j=     | visit a running subagent                             |
| =TAB=         | complete a slash command, or fold the entry at point |
| =M-p= / =M-n= | previous / next sent prompt                          |

A tool call, a folded thought, the task and latest tool call of a
subagent and a pinned line each keep to one line, cut with =…= at the
narrowest window showing the buffer and at most at
=agentel-ui-max-line-width= columns.  They are cut again when the
windows change.  A tool call leads
with the reason the agent gives for it, such as the description of a
Bash command, then its title; unfolding it shows the whole title and
the output.

States of sessions, subagents and background tasks show as one icon
in the header line, the transcript, the pinned lines and the session
list: ⏳ starting, 🏃 running, 🙋 waiting for the user, 💤 idle or
paused, ✅ completed, ❌ failed, 🚫 cancelled and 🔌 exited.  Hovering
an icon names the state, and a state without an icon shows by name in
brackets.  =agentel-ui-state-icons= changes them.

=/resume= lists the earlier sessions of the directory and opens the
chosen one with its history, in the model, effort and mode of the
session it was run in.  =/clear= starts a new conversation in the
same window, buffer name, directory, model, effort and mode, and stops
the old agent, even in the middle of a turn; =/resume= still finds the
old conversation.

Subagents that have not ended and background tasks of the agent, such
as a shell command left running, are pinned between the transcript and
the prompt, so work that outlives a turn stays in view.  Clicking a
subagent there, or =C-c C-j=, visits its buffer.  Background tasks are
reported through the =asyncTasks= capability of the JetBrains AIR
extension, which agentel advertises.

=agentel-focus-mode= shows only what the next input needs: the last
prompt, the questions still open, errors and why the turn ended,
together with the last agent message and the latest thought or tool
call when it came after that message.  To open every session this way:

#+begin_src emacs-lisp
(add-hook 'agentel-chat-mode-hook #'agentel-focus-mode)
#+end_src

** Session list

=M-x agentel-list= (or =C-c C-l=) shows the list in a side window and
moves to it; from inside the list it closes it.  The window stays open
through =C-x 1= and =C-x o= skips it, so the command is the way in and
out.  =agentel-list-side= and =agentel-list-width= place it.  To reach it
from anywhere:

#+begin_src emacs-lisp
(keymap-global-set "C-c a" #'agentel-list)
#+end_src

Each session takes two lines: its state with its project, then its
title.  Subagents follow the session that started them.  Sessions
waiting for the user, or for an answer to one of their subagents, come
first.  Next come the unread sessions, marked with =●=: their turn
ended while their buffer was not shown, and the mark goes once it is.
=n= and =p= move to the next and previous session, subagents included.
=RET= visits a session, =a= answers its oldest question, =c= cancels
its turn and =k= stops it.

* Design

Each feature is one file that hooks into the session registry
(=agentel-session.el=), the connection (=agentel-connection.el=) and the
session buffer (=agentel-chat.el=), so it can be removed by deleting
the file and its =require= in =agentel.el=.

State is written in the way of Elm.  A type of model defines how a
message changes its data (=agentel-store-define=), and a store keeps
the models of one thing and tells its subscribers when they change
(=agentel-store.el=).  How a type looks is defined apart from it
(=agentel-ui-define-view= in =agentel-ui.el=), so the state does not
depend on how it is shown.  Updates and views are to depend on nothing
else: values from outside, such as the state of a session or the width
of the window, come in messages or in the options of the view.  A
model may keep a session or a request to act on it, such as to answer
a question, but its view does not read what they hold.

The conversation of a session (=agentel-conversation.el=) is such a
store, built from the updates of the agent and kept by the session.
Features add their own items to it, such as permission requests, and
the session buffer subscribes to it and only draws it, so a subagent
buffer opened again after it was killed shows its earlier output.  The
session list keeps its own model the same way.

The transcript is drawn like a view of React: after every change of
the conversation the session buffer chooses the items to show and hands
the whole list to a region (=agentel-ui-region.el=), which changes only
the text of the items that are new, left out or changed.  Which items
are shown is a function of the items alone, so focus
(=agentel-focus.el=) replaces that function and knows nothing of how
the transcript is drawn.  Each change compares every item shown once,
which a long session pays for on every chunk of a message.

* Development

=nix develop= provides an Emacs with the dependencies listed in the
=Package-Requires= header of =agentel.el=. agentel itself is not part of
that environment; load it from the working tree:

#+begin_src sh
nix develop -c emacs -L . -l agentel.el
#+end_src

Run the tests and the linters (byte compilation with warnings as
errors, and checkdoc):

#+begin_src sh
nix develop -c make test lint
#+end_src

The tests drive =test/agentel-mock-agent.el=, a scripted stand-in for
claude-agent-acp that runs in the same Emacs. To try the client
without the real agent, add it to =agentel-agents=:

#+begin_src emacs-lisp
(add-to-list 'agentel-agents
             '(mock "emacs" "--batch" "-Q" "-l" "test/agentel-mock-agent.el"))
(agentel-start :agent 'mock)
#+end_src

The mock reacts to words in the prompt: =tool=, =permission=, =ask=,
=subagent=, =background=, =async=, =markdown=, =slow= and =fail=.

After changing =Package-Requires=, regenerate the lock files in =lock/=.
Fetching packages that are not locked yet requires impure evaluation:

#+begin_src sh
nix run --impure .#lock
#+end_src

To update the locked packages, run =nix flake update --flake ./lock=.
